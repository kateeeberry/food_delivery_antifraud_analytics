# Food-delivery marketplace (synthetic) — data dictionary

Synthetic data, no real people. Germany, 5 cities (Berlin, Hamburg, Munich, Cologne, Frankfurt), calendar year 2025.
All money is in **EUR** (the business's base currency). `fx_rates.csv` holds synthetic EUR→USD reference rates
for reporting in USD. Business time zone: Europe/Berlin. Generated by `generate_food_delivery_data.py`
(seed 42; see `generation_params.json`).

This README describes the *structure* only. It deliberately does not define business metrics
(active customer, GMV vs net revenue, churn, "completed order") — those are decisions for the semantic layer.

## Tables

| File | Grain | Columns |
|---|---|---|
| users.csv | one row per account | user_id, signup_ts, city, acquisition_channel, platform, device_id, email_domain |
| restaurants.csv | one row per restaurant | restaurant_id, city, cuisine, price_tier (1-3), commission_rate, onboarded_at |
| couriers.csv | one row per courier | courier_id, city, vehicle_type, hired_at |
| orders.csv | one row per order | order_id, user_id, restaurant_id, courier_id, city, created_at, status, items_count, subtotal_eur, delivery_fee_eur, discount_eur, tip_eur, total_eur, promo_code, delivered_at |
| payments.csv | one row per payment attempt/capture | payment_id, order_id, user_id, method, amount_eur, status, card_fingerprint, created_at |
| promo_redemptions.csv | one row per redeemed promo | redemption_id, order_id, user_id, promo_code, discount_eur, redeemed_at |
| refunds.csv | one row per refund | refund_id, order_id, user_id, amount_eur, reason, created_at |
| support_tickets.csv | one row per ticket | ticket_id, order_id, user_id, category, created_at, resolution_hours |
| fx_rates.csv | one row per day | rate_date, base (EUR), quote (USD), rate (synthetic, not real market data) |
| app_events.csv.gz | one row per app event | event_id, user_id, session_id, event_ts, event_type, platform |

## Keys
users.user_id, restaurants.restaurant_id, couriers.courier_id, orders.order_id are primary keys.
orders.user_id / restaurant_id / courier_id, payments.order_id, refunds.order_id, support_tickets.order_id,
promo_redemptions.order_id, app_events.user_id are foreign keys.

## Notes
- Timestamps are ISO-8601 text; most are UTC with a `Z` suffix. Check formats before parsing.
- Frankfurt launches mid-year. Prices, fees and promo campaigns change during the year.
- Test data and the ground truth of what was injected are NOT in this folder: see `_ground_truth/`
  (keep it away from the analysis/agent until you score your checks).
- Loading to PostgreSQL (Neon): create a schema first (e.g. `food_delivery`), load CSVs as text/raw columns,
  then cast in a separate step. Do not alter the raw tables.
